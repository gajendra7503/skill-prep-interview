A **greedy algorithm** builds the answer one step at a time and, at every
step, takes the option that looks best right now. It never revisits a
choice. When greedy works, it is usually simpler and faster than dynamic
programming. When it does not work, it gives confidently wrong answers, so
the real skill is knowing *when* it is safe.

## Intuition: greedy vs DP

Both greedy and DP need **optimal substructure** (an optimal answer
contains optimal answers to subproblems). Greedy needs one more property:
the **greedy-choice property** — some optimal solution starts with the
locally best choice. DP tries every choice and keeps the best; greedy
commits to one.

| | Greedy | Dynamic programming |
|---|---|---|
| Choices per step | One (the "best-looking") | All, then pick the best |
| Revisits decisions | Never | Implicitly, through the table |
| Typical cost | `O(n log n)` (often a sort) | `O(n * W)`, `O(n^2)`, ... |
| Correctness | Needs a proof | Follows from the recurrence |

## Proving greedy: the exchange argument

The standard proof technique, and what interviewers want to hear:

1. Take any optimal solution `OPT` that differs from the greedy solution.
2. Find the first place they differ. **Swap** `OPT`'s choice for the
   greedy choice.
3. Show the swap does not make `OPT` worse (and keeps it valid).
4. Repeat until `OPT` equals the greedy solution — so greedy is optimal.

If you cannot complete step 3, look for a counter-example; you probably
need DP.

## Problem 1: interval scheduling (activity selection)

A conference room in a Pune office gets meeting requests as `[start, end]`
hours. Book the **maximum number** of non-overlapping meetings.

Candidate rules: earliest start? shortest meeting? fewest conflicts? The
one that works is **earliest end time** — finishing early leaves the most
room for everything else.

```text
time   9   10   11   12   13   14   15
[9,10] ====
[10,11]    ====
[9,12] ============          (rejected: overlaps)
[11,13]         ========
[12,14]              ======== (rejected: starts before 13)
[13,15]                   ========
```

```js
function maxActivities(meetings) {
  const sorted = [...meetings].sort((a, b) => a[1] - b[1]); // by end time
  const chosen = [];
  let lastEnd = -Infinity;
  for (const [start, end] of sorted) {
    if (start >= lastEnd) { chosen.push([start, end]); lastEnd = end; }
  }
  return chosen;
}
console.log(maxActivities([[9, 12], [10, 11], [11, 13], [12, 14], [13, 15], [9, 10]]));
// [ [ 9, 10 ], [ 10, 11 ], [ 11, 13 ], [ 13, 15 ] ]
```

**Exchange argument:** let `g` be the meeting that ends first. If `OPT`
starts with some other meeting `o`, then `o` ends no earlier than `g`, so
swapping `o` for `g` cannot create an overlap. `OPT` stays the same size.

**Complexity:** `O(n log n)` time for the sort, `O(1)` extra space beyond
the output (the copy for sorting is `O(n)`).

A close cousin: "minimum intervals to **remove** so the rest do not
overlap" is `n` minus the activity-selection count:

```js
function eraseOverlap(intervals) {
  const s = [...intervals].sort((a, b) => a[1] - b[1]);
  let removed = 0, lastEnd = -Infinity;
  for (const [a, b] of s) {
    if (a >= lastEnd) lastEnd = b; else removed++;
  }
  return removed;
}
console.log(eraseOverlap([[1, 2], [2, 3], [3, 4], [1, 3]])); // 1
```

## Problem 2: making change — where greedy breaks

Giving change in Indian currency greedily (largest note first) is optimal,
because the ₹ denominations form a **canonical** coin system:

```js
function greedyCoins(amount, coins) {
  const sorted = [...coins].sort((a, b) => b - a);
  const used = [];
  for (const c of sorted) {
    while (amount >= c) { amount -= c; used.push(c); }
  }
  return amount === 0 ? used : null;
}
const INR = [500, 200, 100, 50, 20, 10, 5, 2, 1]; // notes and coins in everyday use
console.log(greedyCoins(2768, INR));
// [
//   500, 500, 500, 500, 500,
//   200,  50,  10,   5,   2,
//     1
// ]

console.log(greedyCoins(6, [1, 3, 4])); // [ 4, 1, 1 ]  -- but [3, 3] uses 2 coins!
```

With coins `[1, 3, 4]`, greedy uses three coins for 6 when two suffice.
For arbitrary denominations, minimum-coin change is a DP problem (see "DP
Patterns: Knapsack, LIS, LCS, Grid & Interval"). Interviewers often ask
exactly this: "Is greedy correct here? Prove it or break it."

## Problem 3: jump game (reachability and minimum jumps)

`nums[i]` is the maximum jump length from index `i`. Can you reach the end?
Track the **farthest reachable index**; if you ever stand beyond it, you
are stuck.

```js
function canReachEnd(nums) {
  let reach = 0;
  for (let i = 0; i < nums.length; i++) {
    if (i > reach) return false;
    reach = Math.max(reach, i + nums[i]);
  }
  return true;
}
console.log(canReachEnd([2, 3, 1, 1, 4]), canReachEnd([3, 2, 1, 0, 4])); // true false
```

For the **minimum number of jumps**, think of BFS levels: every index
reachable with `k` jumps forms a window; the next window ends at the
farthest point reachable from the current one.

```js
function minJumps(nums) {
  let jumps = 0, curEnd = 0, farthest = 0;
  for (let i = 0; i < nums.length - 1; i++) {
    farthest = Math.max(farthest, i + nums[i]);
    if (i === curEnd) { jumps++; curEnd = farthest; }
  }
  return jumps;
}
console.log(minJumps([2, 3, 1, 1, 4])); // 2
```

Both run in `O(n)` time and `O(1)` space — far better than the `O(n^2)` DP.

## Fractional vs 0/1 knapsack

A spice trader's truck carries 50 kg. If items can be **split**, sort by
value per kg and take the best first — greedy is optimal:

```js
function fractionalKnapsack(items, capacity) {
  const sorted = [...items].sort((a, b) => b.value / b.weight - a.value / a.weight);
  let total = 0;
  for (const { weight, value } of sorted) {
    if (capacity === 0) break;
    const take = Math.min(weight, capacity);
    total += value * (take / weight);
    capacity -= take;
  }
  return total;
}
console.log(fractionalKnapsack([
  { name: "saffron", weight: 10, value: 60000 },
  { name: "cardamom", weight: 20, value: 50000 },
  { name: "pepper", weight: 30, value: 36000 },
], 50)); // 134000  (₹1.34 lakh)
```

If items **cannot** be split (0/1 knapsack), the same greedy rule fails and
you need DP.

## Common mistakes

- **Sorting by the wrong key** — start time instead of end time in interval
  scheduling. Test every candidate rule against a small counter-example.
- **Assuming greedy works for coins** with arbitrary denominations.
- **No proof.** "It passed my three examples" is not an argument. State the
  exchange argument, even informally.
- **Off-by-one on touching intervals** — decide whether `[1,2]` and `[2,3]`
  overlap (here they do not, hence `start >= lastEnd`).
