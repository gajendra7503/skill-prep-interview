A **tree** lets each node have several children, modelling hierarchies — an
org chart, folders on disk, the HTML DOM. In a **binary tree** each node has
at most two: `left` and `right`. Tree questions test recursion (see
"Recursion Fundamentals"): almost every solution is "solve left, solve
right, combine".

## Vocabulary

```text
              1          <- root (depth 0)
            /   \
           2     3       <- 2 and 3 are children of 1, siblings of each other
          / \     \
         4   5     6     <- 4, 5, 6 are leaves (no children)

height = 2 (edges, root to deepest leaf); subtree at 2 = { 2, 4, 5 }
```

| Term | Meaning |
|---|---|
| Depth of a node | edges from the root down to it |
| Height of a tree | edges on the longest root-to-leaf path (some count nodes — say which) |
| Complete binary tree | all levels full except possibly the last, filled left to right |
| Balanced | height is O(log n); a skewed tree degrades to height n - 1 |

## Representing a tree in JavaScript

```js
class TreeNode {
  constructor(val, left = null, right = null) {
    this.val = val; this.left = left; this.right = right;
  }
}

// Build from level-order array where null means "no node" (a common test format)
function buildTree(arr) {
  if (!arr.length || arr[0] === null) return null;
  const root = new TreeNode(arr[0]);
  const queue = [root];
  let i = 1, head = 0;
  while (i < arr.length) {
    const node = queue[head++];
    if (arr[i] != null) queue.push((node.left = new TreeNode(arr[i])));
    if (arr[++i] != null) queue.push((node.right = new TreeNode(arr[i])));
    i++;
  }
  return root;
}

const root = buildTree([1, 2, 3, 4, 5, null, 6]); // the tree drawn above
```

## Depth-first traversals

The three DFS orders differ only in **when** you visit the current node
relative to its subtrees:

| Order | Sequence | Result for the tree above | Typical use |
|---|---|---|---|
| Preorder | node, left, right | 1 2 4 5 3 6 | copy / serialise a tree |
| Inorder | left, node, right | 4 2 5 1 3 6 | sorted order in a BST |
| Postorder | left, right, node | 4 5 2 6 3 1 | delete a tree, compute sizes bottom-up |

```js
function preorder(node, out = []) {
  if (node) { out.push(node.val); preorder(node.left, out); preorder(node.right, out); }
  return out;
}
function inorder(node, out = []) {
  if (node) { inorder(node.left, out); out.push(node.val); inorder(node.right, out); }
  return out;
}
function postorder(node, out = []) {
  if (node) { postorder(node.left, out); postorder(node.right, out); out.push(node.val); }
  return out;
}

console.log(preorder(root).join(" "));  // 1 2 4 5 3 6
console.log(inorder(root).join(" "));   // 4 2 5 1 3 6
console.log(postorder(root).join(" ")); // 4 5 2 6 3 1
```

Each node is visited once: **O(n) time**. The call stack holds one frame per
level: **O(h) space** — O(log n) balanced, O(n) skewed. A skewed tree with
lakhs of nodes can overflow the stack, so interviewers ask for the
**iterative** version too:

```js
function inorderIterative(root) {
  const out = [], stack = [];
  let cur = root;
  while (cur || stack.length) {
    while (cur) { stack.push(cur); cur = cur.left; } // go as far left as possible
    cur = stack.pop();
    out.push(cur.val);                                // visit
    cur = cur.right;                                  // then the right subtree
  }
  return out;
}
console.log(inorderIterative(root).join(" ")); // 4 2 5 1 3 6
```

## Level-order traversal (BFS)

Visit the tree level by level using a queue (see "Stacks & Queues"). Process
the queue in batches of its current size to know where each level ends.

```js
function levelOrder(root) {
  if (!root) return [];
  const levels = [];
  let queue = [root];
  while (queue.length) {
    const next = [], level = [];
    for (const node of queue) {
      level.push(node.val);
      if (node.left) next.push(node.left);
      if (node.right) next.push(node.right);
    }
    levels.push(level);
    queue = next;
  }
  return levels;
}
console.log(JSON.stringify(levelOrder(root))); // [[1],[2,3],[4,5,6]]
```

O(n) time; O(w) space for the widest level w (about n/2 in a complete tree).
A fresh `next` array per level avoids `shift()`, which is O(n) per call.

Zigzag order, right-side view and per-level averages are small changes to
this loop.

## Interview problem: maximum depth

**Pattern:** postorder recursion — combine answers from children.

```js
const maxDepth = (node) =>
  node ? 1 + Math.max(maxDepth(node.left), maxDepth(node.right)) : 0;
console.log(maxDepth(root)); // 3  (counts nodes on the longest path)
```

## Interview problem: diameter of a binary tree

The **diameter** is the edge count of the longest path between any two
nodes, which need not pass through the root. The longest path *through* a node has `height(left) + height(right)` edges
(heights counted in nodes). Compute heights bottom-up, update a running best
at every node, and return only the height upward — this "return one thing,
track another" trick recurs often.

```js
function diameter(root) {
  let best = 0;
  const height = (node) => {
    if (!node) return 0;
    const l = height(node.left), r = height(node.right);
    best = Math.max(best, l + r);  // longest path through this node
    return 1 + Math.max(l, r);     // height reported upward
  };
  height(root);
  return best;
}
console.log(diameter(root));                                     // 4  (4-2-1-3-6)
console.log(diameter(buildTree([1, 2, null, 3, 4, 5, null, 6]))); // 4  (5-3-2-4-6, skips the root)
```

Calling a separate `height()` from every node would be O(n²); computing it
in the same pass keeps it O(n).

**Common mistakes:** a missing `null` base case ("cannot read properties of
null"), mixing edge-height and node-height conventions, `queue.shift()` in
a tight loop on huge trees, and recomputing subtree heights at every node.

### Try it yourself

1. Write `invertTree(root)` that mirrors a tree (swap every left and right),

2. Return the **right-side view**: the last node of each level from
