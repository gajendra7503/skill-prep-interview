A recursive function solves a problem by calling itself on a **smaller
version of the same problem**. Trees, graphs, backtracking and dynamic
programming are all built on recursion, so it pays to make it feel
mechanical now.

## The two parts every recursive function needs

1. **Base case** — the smallest input, answered directly without recursion.
2. **Recursive case** — break the input down, call yourself on the smaller
   piece, and combine the result.

```js
function factorial(n) {
  if (n <= 1) return 1;            // base case
  return n * factorial(n - 1);     // recursive case: smaller n
}
console.log(factorial(5), factorial(0)); // 120 1
```

The "leap of faith": when writing the recursive case, *assume* the call on
the smaller input already works. You only need to answer, "Given the answer
for n - 1, how do I get the answer for n?"

Forget the base case, or fail to make progress towards it, and the calls
never stop — Node throws `RangeError: Maximum call stack size exceeded`.

## What actually happens: the call stack

Every call gets a **stack frame** holding its arguments and local variables.
A frame stays on the stack until its call returns.

```text
factorial(4)                       stack grows down, then unwinds up
  4 * factorial(3)                 
        3 * factorial(2)           
              2 * factorial(1)     
                    return 1        <- base case reached
              return 2 * 1 = 2
        return 3 * 2 = 6
  return 4 * 6 = 24
```

Node's stack is limited. A trivial recursive function on Node 24 managed
roughly 9,600 frames on our machine before throwing a `RangeError`; the
exact number depends on frame size and settings. V8, the engine behind Node
and Chrome, does **not** perform tail-call optimisation, so even a
"tail-recursive" function uses one frame per call. For inputs that may be
deep — say a linked list of 10 lakh nodes — prefer a loop.

## Recursion on arrays and strings

Pass an index rather than slicing, so each call is O(1) and no copies are
made:

```js
function sum(arr, i = 0) {
  if (i === arr.length) return 0;
  return arr[i] + sum(arr, i + 1);
}
console.log(sum([499, 299, 1200])); // 1998
```

Writing `sum(arr.slice(1))` instead would copy the array at every level,
turning O(n) time into O(n²).

## Analysing recursive functions

- **Time** = number of calls × work per call. Drawing the **recursion tree**
  helps count the calls.
- **Space** = maximum stack depth × space per frame (plus anything you
  allocate).

`sum` makes n calls doing O(1) work each: O(n) time and O(n) stack space.
Now look at naive Fibonacci, where each call branches twice:

```js
let calls = 0;
function fib(n) {
  calls++;
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}
console.log(fib(10), calls); // 55 177
calls = 0;
console.log(fib(30), calls); // 832040 2692537
```

```text
                fib(5)
            /           \
        fib(4)          fib(3)        <- fib(3) is computed twice,
       /     \          /    \           fib(2) three times...
   fib(3)  fib(2)   fib(2)  fib(1)
```

The tree roughly doubles at every level, so time is exponential (often
quoted as O(2ⁿ)), while space is only O(n) because the stack holds just one
root-to-leaf path at a time. Caching repeated results fixes the time — that
idea is the heart of "Dynamic Programming Fundamentals".

| Recurrence shape | Example | Time |
|---|---|---|
| one call on n - 1, O(1) work | `sum`, `factorial` | O(n) |
| one call on n / 2, O(1) work | fast power | O(log n) |
| two calls on n - 1 | naive Fibonacci, Hanoi | O(2ⁿ) |
| two calls on n / 2, O(n) work | merge sort | O(n log n) |

## Problem: fast exponentiation

Compute xⁿ. A loop multiplies n times: O(n). Recursion lets us **halve**
the problem: x¹⁰ = (x⁵)², and x⁵ = (x²)² × x.

```js
function power(x, n) {
  if (n === 0) return 1;
  if (n < 0) return 1 / power(x, -n);
  const half = power(x, Math.floor(n / 2));   // compute once, reuse
  return n % 2 === 0 ? half * half : half * half * x;
}
console.log(power(2, 10), power(2, -2), power(3, 0)); // 1024 0.25 1
console.log(power(1.1, 3));                           // 1.3310000000000004
```

Time O(log n), space O(log n). The classic mistake is writing
`power(x, n / 2) * power(x, n / 2)` — two calls per level brings it back to
O(n). Note the floating-point noise in the last line; it is normal for
decimals.

## Problem: flatten a nested array

`[1, [2, [3, [4]], 5], [[6]]]` should become `[1, 2, 3, 4, 5, 6]`. The
nesting depth is unknown, which is exactly when recursion shines:

```js
function flatten(arr) {
  const out = [];
  for (const item of arr) {
    if (Array.isArray(item)) out.push(...flatten(item)); // recurse into sub-array
    else out.push(item);                                  // base case: a plain value
  }
  return out;
}
console.log(flatten([1, [2, [3, [4]], 5], [[6]]])); // [ 1, 2, 3, 4, 5, 6 ]
console.log([1, [2, [3, [4]], 5], [[6]]].flat(Infinity)); // same, built in
```

Interviewers usually want the hand-written version, then ask about `flat`.

## Problem: Tower of Hanoi

Move n discs from peg A to C using B, never placing a larger disc on a
smaller one. Leap of faith: move n - 1 discs out of the way to B, move the
largest to C, then move the n - 1 discs from B onto C.

```js
function hanoi(n, from, to, via, moves = []) {
  if (n === 0) return moves;
  hanoi(n - 1, from, via, to, moves);
  moves.push(`${from}->${to}`);
  hanoi(n - 1, via, to, from, moves);
  return moves;
}
console.log(hanoi(2, "A", "C", "B")); // [ 'A->B', 'A->C', 'B->C' ]
console.log(hanoi(3, "A", "C", "B").length, hanoi(10, "A", "C", "B").length); // 7 1023
```

It takes 2ⁿ - 1 moves, so time is O(2ⁿ); the stack depth is only n.

### Try it yourself

1. Write a recursive `isPalindrome(s, lo, hi)` that passes indices rather
   than slicing (`"malayalam"` is true, `"kerala"` false), and state its time
   and space complexity.
2. Write `countDigits(n)` recursively for a non-negative integer, handling
   n = 0 correctly.
3. Add a counter to `power` and confirm that `power(2, 1000)` makes about 11
   calls, while the "two calls per level" version makes far more.
