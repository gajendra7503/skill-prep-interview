This lesson ties the previous ones together into a complete `expenses`
resource: Express 5 routes, Zod validation, a Prisma service and the
central error handler. "Walk me through a CRUD endpoint" is a standard
interview prompt, and the strongest answers mention ownership checks, status
codes and where each concern lives. The code is TypeScript, run with `tsx`,
because the Prisma 7 client is generated as TypeScript.

## Layout

```bash
src/
  app.ts                     # express(), middleware, routers, error handler
  server.ts                  # app.listen(), graceful shutdown
  db.ts                      # the single PrismaClient
  errors.ts                  # HttpError and helpers
  expenses/
    expense.schemas.ts       # Zod schemas
    expense.service.ts       # Prisma queries, business rules
    expense.routes.ts        # HTTP: parse input, call service, send status
```

Routes know HTTP; services know the database. That split lets you test the
service without HTTP and swap Prisma later without touching routes.

## Schemas

```ts
// src/expenses/expense.schemas.ts
import { z } from "zod";

export const idParam = z.object({ id: z.coerce.number().int().positive() });

export const createExpense = z.object({
  title: z.string().trim().min(1).max(100),
  amountPaise: z.number().int().positive(),
  category: z.enum(["food", "travel", "rent", "other"]),
  spentOn: z.iso.date(),
  invoiceNo: z.string().max(32).optional(),
});

export const updateExpense = createExpense.partial();
export type CreateExpense = z.infer<typeof createExpense>;
export type UpdateExpense = z.infer<typeof updateExpense>;
```

## The service

```ts
// src/expenses/expense.service.ts
import { prisma } from "../db.js";
import type { CreateExpense, UpdateExpense } from "./expense.schemas.js";

const fields = { id: true, title: true, amountPaise: true, category: true, spentOn: true, invoiceNo: true } as const;

export function list(userId: number) {
  return prisma.expense.findMany({ where: { userId }, orderBy: { spentOn: "desc" }, select: fields });
}

export function get(userId: number, id: number) {
  return prisma.expense.findFirst({ where: { id, userId }, select: fields }); // null if missing or not theirs
}

export function create(userId: number, input: CreateExpense) {
  return prisma.expense.create({
    data: { ...input, spentOn: new Date(input.spentOn), userId },
    select: fields,
  });
}

export function update(userId: number, id: number, input: UpdateExpense) {
  return prisma.expense.update({
    where: { id, userId },             // throws P2025 if missing or owned by someone else
    data: { ...input, spentOn: input.spentOn ? new Date(input.spentOn) : undefined },
    select: fields,
  });
}

export function remove(userId: number, id: number) {
  return prisma.expense.delete({ where: { id, userId } });
}
```

Every query filters by `userId`. Forgetting that is an **IDOR** (insecure
direct object reference) bug: any user could read expense 42 just by
changing the URL. `userId` is always taken from the authenticated user,
never from the request body, and the select list keeps internal columns out
of responses.

## The routes

```ts
// src/expenses/expense.routes.ts
import { Router } from "express";
import * as service from "./expense.service.js";
import { createExpense, idParam, updateExpense } from "./expense.schemas.js";
import { notFound } from "../errors.js";

export const expensesRouter = Router();

expensesRouter.get("/", async (req, res) => {
  res.json({ data: await service.list(req.user.id) });
});

expensesRouter.get("/:id", async (req, res) => {
  const { id } = idParam.parse(req.params);
  const expense = await service.get(req.user.id, id);
  if (!expense) throw notFound("Expense");
  res.json(expense);
});

expensesRouter.post("/", async (req, res) => {
  const expense = await service.create(req.user.id, createExpense.parse(req.body));
  res.status(201).location(`/api/v1/expenses/${expense.id}`).json(expense);
});

expensesRouter.patch("/:id", async (req, res) => {
  const { id } = idParam.parse(req.params);
  res.json(await service.update(req.user.id, id, updateExpense.parse(req.body)));
});

expensesRouter.delete("/:id", async (req, res) => {
  const { id } = idParam.parse(req.params);
  await service.remove(req.user.id, id);
  res.status(204).end();
});
```

Calling `schema.parse()` inside the handler is a TypeScript-friendly
alternative to the `validate()` middleware: the result is fully typed, and
if it throws, Express 5 sends the `ZodError` to the error handler. No
handler has a `try/catch`; every failure flows to one place.

## Wiring errors and the user

```ts
// in the central error handler, before the generic 500
if (err instanceof ZodError) {
  return res.status(400).json({ error: { code: "VALIDATION_FAILED", message: "Invalid request", details: err.issues } });
}
if (err instanceof Prisma.PrismaClientKnownRequestError && err.code === "P2025") {
  return res.status(404).json({ error: { code: "NOT_FOUND", message: "Expense not found" } });
}
if (err instanceof Prisma.PrismaClientKnownRequestError && err.code === "P2002") {
  return res.status(409).json({ error: { code: "DUPLICATE", message: "Invoice number already used" } });
}
```

## Trying it out

```bash
curl -X POST localhost:3000/api/v1/expenses -H "Content-Type: application/json" \
  -d '{"title":"Team lunch","amountPaise":240000,"category":"food","spentOn":"2026-04-03"}'
# 201  Location: /api/v1/expenses/12
# {"id":12,"title":"Team lunch","amountPaise":240000,"category":"food","spentOn":"2026-04-03T00:00:00.000Z","invoiceNo":null}

curl -X PATCH localhost:3000/api/v1/expenses/12 -H "Content-Type: application/json" -d '{"amountPaise":-1}'
# 400 {"error":{"code":"VALIDATION_FAILED", ...}}

curl -X DELETE localhost:3000/api/v1/expenses/12   # 204, empty body
curl localhost:3000/api/v1/expenses/12             # 404 {"error":{"code":"NOT_FOUND","message":"Expense not found"}}
```

PATCH applies only the fields sent, because `partial()` makes them
optional and Prisma ignores `undefined` values in `data`. A PUT would
instead validate with the full `createExpense` schema and replace every
field.

### Try it yourself

Add `PUT /api/v1/expenses/:id` that requires the full body, and make
`GET /api/v1/expenses/:id` return 404 (not 403) for another user's expense.
Then add a `GET /api/v1/expenses/summary` route that returns the total in
paise and a formatted rupee string such as `₹2,400.00` using
`Intl.NumberFormat("en-IN", { style: "currency", currency: "INR" })`.
Register it before `/:id` and explain why the order matters.
