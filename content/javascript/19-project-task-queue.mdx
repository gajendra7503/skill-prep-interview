Time to combine almost everything from this course into one small but
genuinely useful tool: a task queue that runs async jobs with a concurrency
limit, retries failed jobs automatically, and emits events so callers can
observe progress — the kind of utility that shows up in real codebases for
rate-limiting API calls or background job processing.

## 1. The event emitter foundation

Reuse the pub-sub pattern from the design patterns lesson as the base class:

```js
class EventEmitter {
  #listeners = {};

  on(event, callback) {
    (this.#listeners[event] ??= []).push(callback);
    return () => {
      this.#listeners[event] = this.#listeners[event].filter((cb) => cb !== callback);
    };
  }

  emit(event, payload) {
    (this.#listeners[event] ?? []).forEach((callback) => callback(payload));
  }
}
```

## 2. The queue itself: closures for private state, a class for the public API

```js
class TaskQueue extends EventEmitter {
  #concurrency;
  #running = 0;
  #pending = [];

  constructor({ concurrency = 2 } = {}) {
    super();
    this.#concurrency = concurrency;
  }

  add(taskFn, { retries = 0 } = {}) {
    return new Promise((resolve, reject) => {
      this.#pending.push({ taskFn, retries, resolve, reject });
      this.#next();
    });
  }

  #next() {
    if (this.#running >= this.#concurrency || this.#pending.length === 0) return;

    const job = this.#pending.shift();
    this.#running++;
    this.emit("start", job);

    this.#runWithRetries(job)
      .then((result) => {
        this.emit("success", { job, result });
        job.resolve(result);
      })
      .catch((error) => {
        this.emit("failure", { job, error });
        job.reject(error);
      })
      .finally(() => {
        this.#running--;
        this.#next(); // pull the next pending task now that a slot is free
      });
  }

  async #runWithRetries(job) {
    let attempt = 0;
    while (true) {
      try {
        return await job.taskFn();
      } catch (error) {
        attempt++;
        if (attempt > job.retries) throw error; // out of retries, propagate the failure
        this.emit("retry", { job, attempt, error });
      }
    }
  }
}
```

## 3. Using it

```js
const queue = new TaskQueue({ concurrency: 2 });

queue.on("start", ({ taskFn }) => console.log("Starting a task"));
queue.on("retry", ({ attempt }) => console.log(`Retrying, attempt ${attempt}`));
queue.on("failure", ({ error }) => console.error("Task failed permanently:", error.message));

const urls = ["/api/a", "/api/b", "/api/c", "/api/d"];

const results = await Promise.all(
  urls.map((url) =>
    queue.add(() => fetch(url).then((r) => r.json()), { retries: 2 })
  )
);
```

Only 2 requests run at once (`concurrency: 2`), even though all 4 are
submitted immediately — the rest wait in `#pending` until a running slot
frees up. Each individual task gets up to 2 retries before its promise
(and therefore the corresponding entry in `Promise.all`) actually rejects.

## What this project demonstrates

- **Closures and private class fields** (`#pending`, `#running`) keep the
  queue's internal bookkeeping fully encapsulated — nothing outside the
  class can corrupt its state, same guarantee the module pattern gave you
  with plain closures, pre-`class`.
- **Promises wrapping a non-Promise workflow** — `add()` returns a `new
  Promise` whose `resolve`/`reject` are called later, from inside the
  retry/scheduling logic, which is the standard way to make any callback- or
  event-based process awaitable.
- **The event emitter (observer pattern)** lets callers observe progress
  without the queue needing to know anything about what's listening —
  exactly the decoupling benefit from the design patterns lesson.
- **Recursive scheduling** — `#next()` calls itself (via `.finally()`) every
  time a slot frees up, which is what enforces the concurrency limit without
  a separate polling loop.

### Extend it yourself

- Add a `pause()`/`resume()` method that stops `#next()` from pulling new
  tasks without cancelling ones already running.
- Add exponential backoff to the retry delay instead of retrying
  immediately (hint: `await new Promise(r => setTimeout(r, delay))` inside
  `#runWithRetries`).
- Add a `queue.on("drain", ...)` event that fires once `#pending` is empty
  and `#running` reaches 0 — useful for knowing when a whole batch has
  finished.
