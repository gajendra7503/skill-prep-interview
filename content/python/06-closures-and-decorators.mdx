Decorators show up everywhere in real Python — `@app.get`, `@pytest.fixture`,
`@functools.cache` — and interviewers love them because writing one correctly
requires understanding three things at once: functions as values, closures,
and the exact moment decoration happens.

## Functions are first-class objects

A function in Python is an ordinary object. You can assign it to a name, put
it in a list, pass it as an argument, and return it from another function.

```python
def shout(text):
    return text.upper()

speak = shout              # no call, just another reference
print(speak("hi"))         # HI
print(shout.__name__)      # shout

handlers = [str.lower, str.upper, shout]
print([h("Py") for h in handlers])  # ['py', 'PY', 'PY']
```

## Closures capture variables, not values

A closure is an inner function that remembers names from the enclosing
function's scope even after that function has returned. To *rebind* such a
name from the inner function, declare it `nonlocal`.

```python
def make_counter():
    count = 0
    def increment():
        nonlocal count     # without this, count += 1 raises UnboundLocalError
        count += 1
        return count
    return increment

c = make_counter()
print(c(), c(), c())       # 1 2 3
```

## The late-binding trap in loops

Closures look up the variable when the inner function *runs*, not when it is
defined. Every lambda below shares the same `i`, which holds 2 after the
loop finishes:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])        # [2, 2, 2]

# Fix: bind the current value as a default argument (evaluated at def time)
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])        # [0, 1, 2]
```

`functools.partial` is another clean fix. This is the Python counterpart of
the classic JavaScript `var` in a loop question.

## Decorators are just function wrappers

The syntax `@decorator` above `def f` is exactly `f = decorator(f)`, and it
runs once, at definition time (usually import time), not on every call.

```python
import functools
import time

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timed
def add(a, b):
    """Add two numbers."""
    return a + b

print(add(2, 3))     # add took 0.0000s, then 5
print(add.__name__)  # add  (would be 'wrapper' without functools.wraps)
print(add.__doc__)   # Add two numbers.
```

Always use `functools.wraps`. It copies `__name__`, `__doc__`, `__module__`
and `__qualname__`, and sets `__wrapped__` to the original function, which
debuggers, `help()` and `inspect.signature` rely on.

## Decorators that take arguments

`@retry(times=3)` first *calls* `retry(times=3)`, and whatever that returns
must be the real decorator. That means three levels of nesting:

```python
def retry(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except ConnectionError:
                    if attempt == times:
                        raise
        return wrapper
    return decorator

@retry(times=3)      # same as: fetch = retry(times=3)(fetch)
def fetch(url): ...
```

Stacked decorators apply bottom-up: with `@a` above `@b` above `def f`,
you get `f = a(b(f))`, so `a` is the outermost wrapper.
